# Элементы внутри строки: атомарная разметка

Принято 2026-11-13 (предложено 2026-11-12). Нужны упоминания, формулы и картинки в строке, свои эмодзи —
то, что в ProseMirror и Tiptap делают inline-узлами. В GoTipe блок хранит
`TextSpan[]`, строку или ничего (`packages/core/src/types/block.ts`); inline-узлов нет.

## Решение

Элемент внутри строки — **атомарная разметка**: отрезок текста с mark, у которого
в `MarkSpec` стоит `atomic: true`. Текст отрезка — запасное представление элемента:
`@Аня` у упоминания, исходник TeX у формулы, `:party:` у своего эмодзи, alt у
картинки. Обычные эмодзи Unicode остаются текстом без разметки.

Оба движка гарантируют одно и то же:

1. Выделение не попадает внутрь атома: позиция прилипает к ближайшему краю по
   направлению движения.
2. Атомарная разметка не наследуется: текст, набранный у края, её не получает.
3. Удаление, задевшее атом, удаляет его целиком; разметка и замена, задевшие
   атом частично, расширяются на весь атом.
4. `splitBlock` внутри атома переносится на край.
5. Атом — наибольший отрезок с той же атомарной разметкой и теми же атрибутами.
   Соседние одинаковые атомы различает атрибут `key`.

Рендер рисует атом одним нередактируемым элементом (mark view) с текстом как
доступным именем. Markdown задаёт каждая разметка: упоминание —
`[@Аня](mention:user-42)`, формула — `$x^2$`, свой эмодзи — `:party:`, картинка —
`![alt](src)`.

Подсказки по символу (`@`, `:`, `/`) — общая утилита: расширение объявляет символ
и источник вариантов, ядро шлёт события открытия, запроса и выбора; интерфейс
рисует список.

## Почему не inline-узлы

Смешанное содержимое блока меняет JS-движок, преобразования Rust, CRDT, кодек
Markdown, буфер обмена и все рендеры сразу. Атомарная разметка ложится на то, что
оба движка, CRDT и Markdown уже умеют: символы с разметкой. Смещения считают
запасной текст атома — это и есть его длина в документе.

## Следствия

- Модель документа, история, формат обновлений CRDT и буфера обмена не меняются.
- Чужая вставка внутрь атома при совместной работе возможна только с другого
  клиента без п. 1; фильтр транзакций снимает атомарную разметку с чужого текста
  внутри атома.
- Поиск, экспорт и доступность видят запасной текст — упоминание ищется по имени.
- Отвергнуто: символ-заглушка нулевой ширины с атрибутами — невидимый текст
  ломает поиск, экспорт и чтение с экрана.

## Реализация

- `MarkSpec.atomic` в TypeScript и Rust (`#[serde(default)]`), флаг уходит в схему WASM;
  в состоянии вида атомарная разметка несёт `atomic: true` (`MarkView`).
- Правила 1–5 — в двух копиях с одними тестами на оба движка:
  `packages/core/src/engine/atoms.ts` и `crates/gotipe-core/src/atoms.rs`. Каждый шаг
  нормализуется до применения: вставка и `splitBlock` внутри атома переходят к ближнему
  краю (при равенстве — к концу), удаление и разметка расширяются на весь атом. Rust
  записывает нормализованные шаги в `last_steps`, поэтому CRDT и группы ввода видят
  настоящий эффект. Undo восстанавливает атом одним снимком.
- Выделение: `editor/atom-selection.ts` проводит каждое выделение редактора (DOM,
  клавиатура, транзакция, `setSelection`, начало IME) к краю атома по направлению от
  прежней точки (каретка — от прежней головы); диапазон внутри одного атома выделяет
  весь атом в своём направлении. Rust делает то же в `with_valid_selection` и для
  выделения транзакции. Проверка читает уже построенный вид, а без атомарной разметки
  в схеме ничего не стоит. Составной ввод, начатый браузером внутри атома, вставляется
  у края, куда сдвинута каретка модели.
- Наследование: `getMarksAt` не отдаёт атомарную разметку, а сохранённая разметка
  (`storedMarks`) её не держит, поэтому её не получают набранный и составной текст.
- Встроенные расширения (не в пресетах): `Mention`, `InlineMath`, `CustomEmoji`,
  `InlineImage` с командами вставки и `updateAtom` одним шагом. Схема Rust:
  `gotipe_schema::atoms::with_inline_atoms`.
- Тождество: каждый новый атом получает уникальный `key` — случайный у команд и
  импорта HTML, по порядку в документе (`"1"`, `"2"`, …) у читателей Markdown обоих
  движков. Вставка из буфера даёт новый ключ атому, чей ключ уже есть в документе.
  Новый текст атома (`updateAtom` с текстом) — новый атом с новым ключом; новые
  атрибуты ключ сохраняют. Поэтому равные атомы не сливаются, даже став соседями.
- Markdown (TS и Rust, общий `markdown-atoms.json`) читает атомы только по опции
  `atoms`; HTML обоих сериализаторов совпадает по `html-parity.json`, атом из
  нескольких отрезков — один элемент. Импорт HTML (`setContent`, вставка) читает свой
  HTML обратно в атомы, если схема объявляет их разметку, а расширение даёт поддержку
  атомов (ниже), иначе — запасным текстом.
- Поддержка атомов: восстановление после совместной правки и чтение HTML нужны только
  схеме с атомами, поэтому ядро их не импортирует. Их приносит поле расширения
  `atomSupport` (`InlineAtomSupport`, `types/atoms.ts`): объект
  `extensions/atoms/support.ts` есть у `Mention`, `InlineMath`, `CustomEmoji` и
  `InlineImage`, а своя атомарная разметка берёт его у них
  (`atomSupport: Mention.atomSupport`). Ядро вызывает поддержку первого расширения, у
  которого она есть. Правила 1–5, выделение и новые ключи вставки действуют для любой
  атомарной разметки и без неё.
- Подсказки: `defineSuggestion` в `@gotipe/core/extensions`; таблица коротких имён
  эмодзи — отдельный вход `@gotipe/core/emoji`, вне графа ядра.
- Совместная работа: чистая функция `normalizeRemoteAtoms(before, after, isAtomic,
  known?)` сопоставляет атомы по тождеству (тип и `key`) и снимает атомарную разметку
  только с символов, вставленных между прежними краями атома, и с осиротевшего атома —
  чужого текста, оставшегося от атома, удалённого здесь (`known` — последний виденный
  текст атома). Новые, нетронутые, укороченные и переписанные целиком атомы не
  трогаются; атомы с неоднозначным тождеством тоже. Подключено:
  `editor/collaboration.ts` после `bridge.receiveUpdate` вызывает `repairRemote`
  поддержки атомов (`editor/remote-atom-repair.ts`), а редактор отправляет её шаги
  локальной транзакцией с
  `metadata: { addToHistory: false, origin: "repair" }`, чтобы исправление получили все
  реплики. Память `known` пополняется при каждом приёме и перед локальной транзакцией
  для затронутых блоков.
- Отображение атома отдельным элементом ждёт кадров Атласа; React и Vue показывают
  запасной текст.
